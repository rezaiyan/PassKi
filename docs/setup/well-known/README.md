# `.well-known` files for alirezaiyan.com

These files are generated by `./gradlew :androidApp:passkiWellKnown` (output in
`androidApp/build/passki/well-known/`) and are served at:

- `https://alirezaiyan.com/.well-known/assetlinks.json` (Android: Digital Asset Links)
- `https://alirezaiyan.com/.well-known/apple-app-site-association` (iOS: `webcredentials`)

The sample's `passki { }` block in `androidApp/build.gradle.kts` is the source of truth: the Android
package and signing fingerprints come from the Android build, the Apple app ID from
`apple { teamId; bundleId }`.

## Tasks

| Task | What it does |
|------|--------------|
| `./gradlew :androidApp:passkiWellKnown` | Writes `assetlinks.json` and `apple-app-site-association` |
| `./gradlew :androidApp:passkiFingerprints` | Prints package, variant, keystore and SHA-256 per variant, plus the `android:apk-key-hash:` origins for server allow-lists |
| `./gradlew :androidApp:passkiVerify` | Fetches the hosted files from `https://<rpId>` and checks them, and the iOS entitlements, against the build (network) |

`assetlinks.json` has one statement per package the build produces. A build type with
`applicationIdSuffix = ".debug"` gets its own `com.example.app.debug` statement with only the debug
key; `extraFingerprints` (e.g. Play App Signing) go to packages of non-debuggable variants.

## Fingerprints

The committed `assetlinks.json` lists the fingerprint of the debug keystore
(`~/.android/debug.keystore`) that signs the sample here. On another machine the debug key differs:
regenerate with `passkiWellKnown`, or add your fingerprint via
`passki { android { extraFingerprints.add("AB:CD:…") } }`.

## Keystore passwords

Keystore passwords are read from the Android signing configs. They are **not** tracked task inputs
(up-to-date checks use the keystore file contents, alias and type only), so they never end up in the
build cache. They are, however, stored in the configuration-cache entry (under `.gradle/configuration-cache/`,
encrypted by Gradle with a key kept in the Gradle user home), which stays on the local machine;
don't share or upload that directory.
